# ContextCue 使用指南

[返回 README](../README.zh-CN.md) · [English](./guide.md)

从当前应用或浏览器窗口唤起 ContextCue，默认进入 Ask AI：提问以理解信息，或说明意图生成草稿。独立的 Quick writing 快捷键可直接生成写作建议。每次唤起都创建新的页面会话，只使用本次窗口截图、当前输入和本会话内容，不带入之前窗口的问答、候选或长期记忆；AI 问答还可以关闭页面上下文。输入框不是前提：macOS 识别到可编辑控件时支持直接写入，否则仍可复制建议。你来检查文本并决定如何使用，ContextCue 不会自动提交或发送。

“本地优先”指记忆和设置保存在本机，不代表模型推理一定在本地运行。使用截图或相关上下文生成内容时，这些数据会发送给你配置的模型服务商。

> [!IMPORTANT]
> 基于截图的写作建议和带页面上下文的 AI 问答需要支持**图片输入**的模型。不带页面上下文的 AI 问答也可以使用纯文本模型。部分兼容服务会静默忽略不支持的图片输入；ContextCue 会标记已知的纯文本模型，并阻止向标记为纯文本的模型发送基于截图的请求。

## 功能概览

| | 能力 | 具体行为 |
|---|---|---|
| ⚡ | **任意窗口唤起** | 在应用或浏览器页面按一次全局快捷键，无需先聚焦输入框。 |
| ✦ | **流式 AI 问答** | 默认主入口，提问流式显示回答，明确的写作请求生成可修改与插入的草稿。 |
| ✦ | **自动判断文本任务** | 生成回复、表单字段文本、新文案、改写、搜索词和文本补全。 |
| ↔️ | **轻量候选浮窗** | 使用双指滑动、横向手势、圆点或方向键切换建议。 |
| ↵ | **精确写回但不提交** | macOS 会校验原输入控件后插入、替换选区或替换字段；失败时只复制。 |
| ✦ | **就地修改，多个候选** | 在当前建议下方输入修改要求，新候选逐条出现，可随时返回原始建议。 |
| 🧠 | **保留本地记忆** | 既有 Markdown 文档、事实和历史记录仍可在本机管理，不参与当前页面会话。 |
| ✓ | **首次使用引导** | 连接服务商、验证图片能力与权限，再用虚构对话完成一次建议体验。 |
| ◉ | **多个模型服务商** | 保存多个 Responses 或 Chat Completions 配置，并随时切换默认模型。 |
| ◷ | **本地用量统计** | 按时间范围查看服务商返回的 Token 数、模型用量分布和请求历史。 |
| 🔒 | **系统级密钥保护** | 使用 Electron `safeStorage` 和操作系统钥匙串分别加密 API Key。 |

窗口定位使用操作系统提供的前台窗口 ID，不依赖应用名称白名单。微信、Slack、Gmail 等渠道标签只作为可选的模型上下文，不参与截图窗口的选择。

搜索辅助用于生成搜索词，不会执行联网搜索。

## 工作方式

主入口遵循以下流程：

```text
当前应用或浏览器窗口
  └─ Ask AI 快捷键 → 截取可见窗口，创建独立会话
      └─ 用户提问或说明写作意图 → 一次模型请求
          ├─ 理解类问题 → 流式回答 → 继续追问
          └─ 写作类请求 → 校验草稿 → 修改 → 复制或插入
```

Quick writing 快捷键保留直接生成 1–5 条候选的路径，不要求先输入问题。

浮窗跟随唤起时的原生窗口。切换到其他应用或窗口时会暂时隐藏，返回后恢复原会话；在同一页面内切换输入框不会隐藏浮窗。检测到原窗口页面标题变化，或会话超过五分钟时，会使截图上下文失效并取消请求，但保留候选、修改要求和可见问答，供继续阅读与复制。失效后可返回 Ask AI 点击刷新，或重新唤起，才能继续使用 AI 或插入文字。每次重新唤起都会重新截图并创建新会话，即使仍在同一窗口中。写入前还会再次校验原输入目标。

候选浮窗默认随内容调整高度。需要更大的阅读区域时，可拖动窗口边缘或右下角；右下角在悬停或键盘聚焦时显示轻量弧形提示。阅读宽度在本次应用运行期间保留；切换候选或重新唤起时，高度重新随内容适配。手动调整的高度仅用于当前候选。AI 问答单独保留自己的大小。聚焦右下角手柄后可用方向键微调，按住 Shift 可加大步幅。

Ask AI 在新安装中默认使用 `⌘ ⇧ Space` / `Ctrl ⇧ Space`；Quick writing 默认使用 `⌘ ⇧ Enter` / `Ctrl ⇧ Enter`。升级保留已有快捷键。浮窗显示前先保存当前页面截图，提交问题时不会重新截取已经切换的标签页。发送问题前可以关闭页面上下文；无法截图时会说明原因，并允许不带页面上下文继续提问。AI 问答使用你的问题、浮窗内最近的问答记录和可选截图，不会附带长期记忆文档。关闭浮窗后截图和内存问答记录清除。顶部显示已截取页面的来源，关闭上下文后显示 **Page off**。**Summarize / Explain / Draft a reply / Rewrite** 会将提问填入输入框，检查后再发送；Enter 发送，Shift + Enter 换行。


截图来源标签旁的刷新按钮会重新截取原窗口，并开始新会话，清除旧问答、候选及未发送输入；悬停标签可查看截图时间。刷新失败保留原内容；刷新时若切换到其他窗口，则拒绝捕获。切换窗口后，请在目标窗口重新按快捷键。

候选圆点与序号合并在顶部区域，可以点击，也可通过 Tab 聚焦后按 Enter / Space 选择。点击首页工具栏的 **Revise**，在当前候选下方展开 **How should this change?** 输入区。浮窗保持左上角位置和宽度，向下扩展至最多 540px；屏幕下方空间不足时限制高度。上方始终保留当前候选预览，长消息与下方修改区分别滚动，输入要求时不会把原文卷走。**Collapse** 仅收起修改区并保留要求；右上角 **X** 关闭整个浮窗。**Shorter / Warmer / More direct** 会追加到修改要求末尾，保留已有背景。Enter 换行，输入框内方向键移动光标，`⌘ / Ctrl + Enter` 提交修改，Esc 优先收起输入区。

明确的写作请求会在完整结果校验后自动打开草稿候选；如意图不清，模型应先简短追问。输出类型由模型判断，不额外调用分类接口。返回 Ask AI 保留可见问答，**Open draft** 可重新打开最近草稿。

每次修改使用提交时选中的候选、用户要求和本会话原始截图；若草稿是在关闭页面上下文时生成，后续修改也不附带截图或页面元数据，并支持纯文本模型。修改通过一次流式请求生成设置中的候选数量（1–5 条，通常为 3 条）。每条完整且通过解析的候选准备好后立即显示；后续候选到达不会自动切走正在阅读的一条。**Revised · 1/3** 表示修改后的候选组。若服务商忽略流式请求、返回普通 JSON，则等待完整结果后展示。首次生成建议仍等待完整响应，本次渐进展示用于 Revise。

成功后自动收起输入区，结果直接成为候选，不再经过独立 Edit 页面或 Save draft 步骤。**Back to original suggestions / Show revised suggestions** 可在原始组和最近一次修改组之间切换，不无限追加历史版本。**Stop** 保留已经完成的候选和修改要求；请求失败时恢复修改前的候选组，并保留要求用于重试。复制或插入仍需单独点击，不会自动发送消息。从 Ask AI 返回也会保留候选组及当前选择。

页面问答历史由主进程按会话隔离，最多使用最近三轮完整问答。建议与修改请求各有 45 秒总超时（包含可能的一次格式恢复重试）；关闭或更换会话会取消请求并丢弃迟到结果。

## 快速开始

### 运行要求

- Node.js 22.12+
- npm 10+
- macOS、Windows 或 Linux
- 已配置模型的 API Key；基于截图的功能需要图片输入能力，关闭页面上下文的 AI 问答不需要

### 本地运行

```bash
git clone https://github.com/jastfkjg/ContextCue.git
cd ContextCue
npm install
npm run dev
```

### 第一次提问或起草

1. 首次启动会显示 **Setup guide**：选择服务商，填写图片模型 ID 和 API Key；接口地址与协议位于 **Connection details**。高级配置仍可在 **Settings** 中修改。
2. 点击 **Verify model**，用随机生成的色块图片验证连接和图片理解能力；该检查不读取真实窗口。再检查屏幕权限，必要时打开系统设置授权并点击 **Check again**。macOS 插入权限为可选，未授权仍可复制。
3. 在虚构对话下的 Ask AI 输入框提问，或点击 Draft a reply 填入明确的回复意图。阅读回答或选择草稿，最后点击 **Start using ContextCue** 进入日常首页。测试图片和示例请求可能产生服务商费用。可以稍后配置，也可以随时从侧栏重新打开引导；完成状态会保存，已有配置用户升级后无需强制重做。
4. 打开任意应用或网页；需要直接写入时，可先聚焦输入框。
5. macOS 按 `⌘ ⇧ Space`，Windows / Linux 按 `Ctrl ⇧ Space`。
6. 输入问题或写作意图并提交。解释直接阅读；草稿可切换、修改、复制或插入，绝不会自动提交。

如需直接生成写作候选，按 `⌘ ⇧ Enter` / `Ctrl ⇧ Enter`。升级用户请以设置中显示的快捷键为准。候选浮窗里的 **Ask AI** 可以返回同一会话。两个快捷键都可以在设置中修改；如果任意快捷键注册失败，ContextCue 会同时保留原来的两个快捷键。

### 环境变量

也可以用环境变量提供默认模型连接：

```bash
cp .env.example .env
export CONTEXTCUE_API_KEY="your-key"
export CONTEXTCUE_API_BASE_URL="https://api.openai.com/v1"
export CONTEXTCUE_MODEL="your-vision-model"
npm run dev
```

不要提交 `.env` 文件。

## 模型服务商

每个模型配置都拥有独立的接口地址、协议、图片输入能力和加密 API Key。

| API 格式 | 适用情况 |
|---|---|
| **Responses API** | 服务商明确支持 OpenAI 风格的 `/responses` 接口。 |
| **Chat Completions** | 服务商提供兼容的 `/chat/completions` 接口，包括许多云端及本地服务。 |

设置中的 **Test connection** 验证接口连通性和密钥；首次引导中的 **Verify model** 额外发送随机色块图片并核对识别结果，不能把纯文本接口返回 OK 当成图片能力验证。该探测不保证所有截图都能正确理解。已有的 DeepSeek 纯文本模型会在配置迁移时标记为 text-only；未知模型可以在设置中手动修正。

## 本地记忆

在 **Memory** 中仍可编写和预览既有 Markdown 文档，保留个人背景、写作偏好、联系人或项目笔记。文档的 Global / Channel / Person 作用域与启用状态作为兼容元数据保留，但不参与页面限定会话。之前保存的事实仍可查看和删除。

文档名称以 `.md` 结尾，但内容并非独立的 Markdown 文件，而是与其他本地数据一起保存在 Electron 对应平台的 `userData/contextcue-data.json` 中：

| 数据 | 用途 |
|---|---|
| `documents` | 可编辑的 Markdown 上下文、作用域和启用状态 |
| `profile` | 为兼容旧数据和回退使用而保留的个人资料 |
| `contacts` | 联系人关系、渠道、备注和专属沟通语气 |
| `facts` | 用户明确保存的偏好、长期事实和跟进事项 |
| `acceptedReplies` | 为兼容旧数据保留的名称，记录最近 100 条已采用建议及其任务/目标元数据 |
| `tokenUsage` | 最多 5,000 条本地请求记录，包括服务商返回的 Token 数和模型元数据 |
| `settings` | 模型、候选数量、语言、快捷键和浮窗偏好 |

页面限定的写作建议、修改和 AI 问答不加载这些文档、联系人、事实或历史采用文本。浮窗中的复制、插入和修改也不再自动追加长期采用记录；旧数据不会删除。需要额外背景时，请在当前会话中明确输入。旧版兼容接口和存储结构仍保留。

## Token 用量

打开 **Usage**，可按模型及最近 7 天、最近 30 天或全部保留记录筛选，查看输入/输出 Token 总量、每日趋势、模型用量分布和最近请求历史。Token 数来自服务商响应；未返回的数值显示为 **Not reported**，不会自动估算。用量记录保存在本机，不等同于服务商账单。

## 隐私边界

- 页面截图由用户主动唤起或刷新产生；窗口列表和权限检查也会在本机读取缩略图，但不上传。首次引导的图片验证和示例只上传人工构造的图片。
- 用于写作建议或页面问答的截图会发送给用户配置的模型服务商，但不会写入长期记忆文件。关闭 AI 问答的页面上下文后，问题请求不再包含截图和页面元数据；这不代表打开浮窗时没有进行截图。
- 截图和页面元数据中的文字都被视为不可信数据，而不是系统指令。
- 长期记忆保留在本机，不发送给页面限定的建议、修改或问答请求。
- 保存后，API Key 不会再次暴露给渲染进程。
- 当 macOS 辅助功能适配器识别到密码、验证码等敏感焦点输入控件时，会阻止快捷唤起流程。这不保证识别所有敏感内容：截图不会自动脱敏，未识别到的控件及其他平台也没有同等的字段级检查。
- 应用建议前会先复制文本；如果原输入框发生变化，则不会向错误字段粘贴。
- ContextCue 不会在后台录屏，也不会自动提交表单或发送消息。

> [!NOTE]
> 以上是 ContextCue 自身的产品边界，不代表第三方模型服务商的数据政策。处理敏感会话前，请检查对应服务商的数据保留条款。

## 技术结构

```text
Electron 主进程
  ├─ desktopCapturer / screencapture：可见窗口截图
  ├─ globalShortcut：系统级快捷唤起
  ├─ safeStorage：逐模型加密 API Key
  ├─ Accessibility 输入目标适配：读取并校验焦点控件
  ├─ clipboard + 系统自动化：精确写回与安全回退
  ├─ MemoryStore：本地 JSON 记忆与配置迁移
  └─ Model adapter：Responses + Chat Completions

强类型 Preload Bridge
  └─ 最小化 IPC 接口

React 渲染进程
  ├─ 首次引导与日常快捷首页
  ├─ 可滑动候选建议
  ├─ Markdown 记忆文档与已保存事实
  ├─ Token 用量与请求历史
  ├─ channel 与窗口发现
  ├─ 多模型设置
  └─ 与上下文关联的候选建议和流式 AI 问答浮窗
```

浏览器构建使用不联网的预览数据，仅供检查界面。真实截图、全局快捷键、安全密钥存储和跨应用插入必须在 Electron 中运行。

## 开发命令

| 命令 | 用途 |
|---|---|
| `npm run dev` | 启动 Electron 开发模式 |
| `npm run lint` | 执行 TypeScript 检查 |
| `npm test` | 运行单元测试 |
| `npm run test:window` | macOS：用两个同名测试窗口验证原生定位和本地截图，不调用模型 |
| `npm run test:watch` | 以监听模式运行测试 |
| `npm run build` | 构建主进程、Preload 和 Renderer |
| `npm run package` | 生成未打包的桌面应用目录 |
| `npm run dist` | 生成平台安装包 |
| `npm run dist:mac:beta -- --arm64` | 生成临时签名的 macOS 内测包；Intel 使用 `--x64` |

应用会在启动 15 秒后和运行期间每 6 小时检查一次更新。发现新版时通过系统通知和侧边栏提示，也可以打开 **Settings → App updates**，或右键点击托盘图标选择 **Check for Updates…**。

下载由用户点击开始，并显示进度。通过 Developer ID 签名和公证的 macOS 构建可点击 **Restart and update** 完成更新；默认使用临时签名、未经公证的 macOS 内测构建会在应用内下载并校验 DMG，点击 **Open installer** 后退出 ContextCue，把新应用拖入 Applications 并替换旧版。本地记忆和设置保存在应用包之外。

发布流程已支持可选签名、公证、双架构更新包和更新清单。启用签名所需的 GitHub 配置、发布步骤和验证方法见[更新发布指南](./updates.md)。已有的无更新功能版本需要手动安装一次新版，之后才能在应用内获取更新。

## 当前限制

- 当前会缩放窗口截图，尚未提供用户自由框选区域。
- 会话使用唤起时的静态快照，不会自动跟随页面更新。窗口标题未改变的网页内容变化或同名标签页无法可靠区分；页面变化后请刷新或重新唤起。会话目前在创建五分钟后过期。更多交互边界与验收步骤见[交互流程说明](./interaction-flows.md)。
- macOS 会校验焦点输入控件并尝试精确写回；已识别但不支持 AX 写入的控件会回退到校验后的粘贴。未识别到输入控件时（包括 Windows/Linux），建议只提供复制。
- 原生窗口定位和截图已在 macOS 验证；Windows 使用系统前台窗口接口，Linux 需要 X11 和 `xdotool`。受保护窗口或不支持截图的环境仍可使用不带页面上下文的 AI 问答。
- 浏览器暂未提供 DOM 扩展，复杂 iframe、Canvas 编辑器和部分富文本控件只能依赖系统辅助功能树与截图。
- channel 支持基于可见窗口，尚未同步历史 OAuth 消息。
- 局部截图、附近辅助功能文本、本地 OCR/脱敏、语音输入和日历操作仍在规划中。
- 记忆文件当前限制为仅本用户可读，但尚未整体加密；API Key 会单独加密。

ContextCue 仍是早期桌面 MVP，交互思路受到 OKEight 会话内回复流程的启发。生产化工作和后续功能见[产品路线](../TODO.md)。
